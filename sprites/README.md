# Character sprites

Pixel-art characters for the 3/4 top-down view: 13 px wide walk frames in 8 directions, plus attack, hurt and death.

```
npm run sprites           # rebuild sheets/ from data/
npm run check:sprites     # missing-pixel check on every recipe
```

## data/

One JSON file per sprite, exported from the sprite editor. Pixels are palette keys, one character each, `.` empty,
rows joined with `/`.

| Kind | What it is |
|---|---|
| character | Hand-drawn: `frames` (walk: idle + 6 per direction) and `attack` / `hurt` / `death` on their own bigger canvases (`ox`, `oy` place the walk frame inside them so the feet line up) |
| base (`base-male`, `base-female`) | Bald, earless bodies whose palette keys are body parts (k outline, a head, y eyes, n neck, t torso, p hips, U/u upper arm, O/o forearm, H/h hand, Q/q thigh, L/l shin; capitals are his right) |
| layer (`kind: "layer"`) | One drawing per direction (hair, hats, collars, skirts), drawn over a base's idle. `covers`: other body parts it may paint over; `rise: "all"`: follows the walk bounce entirely |
| recipe (`kind: "recipe"`) | A base, a colour per body part, layers, and `tints` (per-recipe layer recolours). Assembled, never drawn. `group` and `needs` (accessories not drawn yet) come from the profession list |

The assembly rules are in `src/sprites/compose.ts`; they're the same ones the editor uses.

## sheets/

Generated by `npm run sprites`. One transparent PNG per sprite and animation (`<id>/walk.png`, `attack.png`,
`hurt.png`, `death.png`): a row per direction, a column per frame. `index.json` says, per animation, the frame size,
the row order, the frame count, fps, where the walk frame sits (`walkAt`), the walk's idle frame and loop, and which
direction plays for one that isn't drawn (`fallback`: death is drawn for E and W only).

## Missing-pixel check

`npm run check:sprites` assembles every recipe and looks for

- **gaps:** empty pixels inside the sprite, such as hair that came away from the head, and
- **no outline:** coloured pixels on the sprite's edge without their outline.

The bases have some of both on purpose (the space between the legs, an open hand), so each frame is compared with
the same frame of its bare base, and only what the layers add is reported, put down to the layer that caused it. It
prints one line per layer and frame, then a total per layer, and exits 1 if it finds anything.
